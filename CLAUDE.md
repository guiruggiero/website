# Website Codebase Reference

## Architecture

This is a **static vanilla JavaScript website** — no framework, no bundler, no transpilation. All JS is written as ES6 modules and loaded directly from HTML via `<script type="module">`. The backend API is a Firebase Cloud Function in `guipt/`.

### Pages and Modules

- `index.html` — main page; loads the GuiPT AI chat interface
- `voice.html` — voice-first homepage candidate (Sonic with takeaway cards instead of a transcript), WIP; see `sonic/CLAUDE.md`
- `resume.html` — portfolio/resume page
- Various external utility pages (`resume-pdf.html`, `scheduling.html`, etc.) using embedded content and with a `noindex` meta tag
- Admin pages (`admin.html`, `admin-firestore.html`, `admin-apps.html`) — see [Admin Area](#admin-area)
- Various redirect pages (`linkedin.html`, `github.html`, etc.) using `modules/redirect.js`
- `modules/` — ES6 modules:
  - `main.js` — orchestrates chat: event listeners, turn flow, history management
  - `ui.js` — DOM manipulation, chat window expand/collapse, loader
  - `guipt.js` — API call to the GuiPT Cloud Function with axios + retry
  - `firebase.js` — Firestore Lite logging (`createLog`, `logTurn`), shared by GuiPT and Sonic via optional collection/extra-field options
  - `sonic.js` — the Sonic voice client loaded by `sonic.html`, with `mic-processor.js` as its AudioWorklet; see `sonic/CLAUDE.md`
  - `voice.js` — fork of `sonic.js` for `voice.html`, rendering cards instead of a transcript
  - `validation.js` — input sanitization, length check, rate limiting (5 msg/min)
  - `localization.js` — i18n, auto-detects browser locale; exposes an async `getLangData()` (not a top-level-await default export — that pattern caused an intermittent WebKit TDZ error, see WEBSITE-23) that callers `await`
  - `theme-toggle.js` — dark/light mode, persisted in localStorage
  - `sentry.js` — error tracking initialization
  - `cookie-banner.js` — Google Analytics consent
  - `shared-head.js` — shared `<head>` injection (GTM, cookie banner CSS, favicons); deliberately skipped by the admin pages
  - `redirect.js` — URL redirection helper
  - `admin-auth.js` — Firebase Auth gate for all admin pages
  - `admin-status.js` — service health cards on `admin.html`
  - `admin-firestore.js` — chat log viewer on `admin-firestore.html`
  - `admin-apps.js` — only runs the sign-in gate on `admin-apps.html`, whose content is static links

### Dev vs. Production Loading

Scripts auto-detect the environment at runtime from a single check — `location.href.includes("ngrok")`. Only an ngrok URL loads the `.js` modules; every other URL, **including `localhost`**, loads `.min.js`. This means the file a page loads is determined by the script tag in the HTML — no webpack aliases or env flags.

Since `.min.js` files are generated by CI and exist only on `prod-min`, a plain `http://localhost:8082/...` page requests files that aren't on disk, gets 404s, and renders permanently blank (`theme-toggle` never runs, so `html { visibility: hidden }` is never flipped — see [Localization](#localization)). Serving locally therefore means either tunneling through ngrok, or appending a `?ngrok` query string to the localhost URL to satisfy the check.

The same split applies one level down, when one module imports another: a static `import` would hardcode one extension, so cross-module imports instead go through an `importModule()` helper (see `main.js`, or `admin-firestore.js` importing `admin-auth.js`) that checks the URL for `ngrok` and picks `.js` or `.min.js` at runtime.

`theme-toggle.js` and `shared-head.js` reference images and styles by root-absolute paths (`/images/...`, `/styles/...`) so they work whatever the page's URL; keep new asset paths in shared modules absolute too.

`loadScript()` (inlined in all 15 pages) sets `script.async = false`: script-inserted elements default to async, so `defer` is a no-op and the scripts race (this caused WEBSITE-40, `getLangData is not a function`). Don't revert it.

Cloudflare Rocket Loader is disabled zone-wide (since 2026-10-09, for WEBSITE-45). Don't suggest re-enabling it. If `rocket-loader` frames reappear in Sentry, purge the Cloudflare cache, because cached HTML may still have rewritten script tags.

### Localization

All UI strings live in `locales/en.js` and `locales/pt.js`. When adding new UI text, add keys to both locale files. The language is auto-detected from `navigator.language`.

`global.css` sets `html { visibility: hidden }` to avoid a flash of untranslated content; it's `localization.js` (pulled in by `theme-toggle.js`) that flips it back to visible once translation runs (or immediately, if the page's language already matches the default). Any new page must load `theme-toggle` or it renders permanently blank.

### Linting

The CI pipeline doesn't run lint — it only minifies and deploys.

## Admin Area

`admin.html`, `admin-firestore.html` and `admin-apps.html` live at the repo root, not in an `admin/` subdirectory — `minification.yml` globs HTML with `find . -maxdepth 1`, so anything nested there would ship to `prod-min` unminified.

**Access control** is two-layered:

- All pages sit behind **Cloudflare Zero Trust** — one self-hosted application on `guiruggiero.com` named `Admin`, covering all three via the path `guiruggiero.com/admin*` (if the wildcard doesn't take, add each page as a separate path). Its policy is the reusable "Friends and family" allow rule (the owner's and their wife's emails), shared with the `Apps` application below. That's why the apps page is `admin-apps.html`, not `apps.html`
- All pages have a second gate on top: **Firebase Auth** Google sign-in, in `modules/admin-auth.js`. This is the gate that matters functionally — `firestore.rules` grants `read` only to the owner's UID, so without it `admin-firestore.html` just gets `PERMISSION_DENIED`, and `admin.html`'s On Air buttons send the ID token to Guiddleware, which rejects any UID but the owner's. Zero Trust doesn't cover the Guiddleware URL, so that check is the only protection for the route

**Shared layout conventions** for all pages:

- They deliberately skip `shared-head.js`, since it injects GTM (Google Analytics) and the cookie banner CSS — neither belongs on an internal page — so they declare their own favicons inline, carry `noindex, nofollow` and show no cookie consent. They also skip localization (`data-i18n`); the admin UI is English-only
- None has an in-page `<h1>` — page-level controls go in the header's right slot, where public pages carry social links (`Refresh` plus the last-checked time on `admin.html`; the same on `admin-firestore.html`, where `Refresh` re-runs the current query), `admin-apps.html` has no controls there, and the centered tabs between the three pages are the first thing under it
- `admin.css` overrides `main` to the site's standard 750px so all pages line up with the header and footer
- Secondary buttons (Refresh, the date presets, the On Air sign's Off/Yellow/Red) share one `.small-button` class; JS finds the date presets by `[data-days]`, not by class
- Card headers are plain `<div class="card-header">`, never `<header>`: `global.css` styles the bare `header` selector as `position: fixed; height: 60px`, so a nested `<header>` is pulled out of flow and stacks on top of the site header

### Apps Page

`admin-apps.html` is a launcher: one card per self-hosted ArtCraft app, each with a `withicons-glass` Iconify icon. Hosted apps (PdfCraft, plus PhotoCraft and SoundCraft once set up) come first as large, fully clickable cards linking to the app's own URL; the ones not hosted yet (FilmCraft, FigCraft, CADCraft, VectorCraft) are small, greyed-out `(soon)` cards with no link. Move a card up and make it a link when its app goes live. The Worker injects the site's GR favicons and sets the page title to `<App> - Gui Ruggiero`, since the releases' own `index.html` has neither. The apps themselves are not built here and never reach `prod-min`. Each app's web build is hosted from `apps/<name>/`: a Worker (`src/index.js`) serving the release's static files from an R2 bucket, because the builds' WASM files exceed the 25 MiB per-file limit of Workers static assets and Pages. Only PdfCraft is set up so far, PhotoCraft and SoundCraft are next. Deploy the Worker with `npm run deploy` from the app's folder. The bucket's content comes from the app's latest GitHub release: `npm run update-app` (`apps/update.js`, per-app settings in its `apps` map) downloads it, uploads the files with `index.html` last, records them in `manifest.json` in the bucket and deletes the previous version's files; it only acts when the release tag differs from the manifest's. `apps-update.yml` runs it monthly for every app folder, using the repo secrets `CLOUDFLARE_R2_STORAGE` (scoped to R2 only, separate from the cache-purge token) and `CLOUDFLARE_ACCOUNT_ID`. Adding an app means a new entry in the `apps` map. A manually downloaded zip stays out of git (`apps/*/release/`). The `Open` URLs are `<name>.guiruggiero.com`, one Zero Trust application named `Apps` covering `*craft.guiruggiero.com`, with the same policy and IdP as `Admin`; both are hidden from the app launcher, since a wildcard tile can't link anywhere. The apps have no second gate like the Firebase sign-in, so this policy is their only protection.

### Chat Log Viewer

`modules/admin-firestore.js` uses the **full** Firestore SDK rather than the Lite build in `modules/firebase.js`, because it needs `getDocs` queries. It reuses the app instance exported by `admin-auth.js` instead of initializing a second one.

- User turns are rendered with `textContent`, never `innerHTML` — unsanitized input from anonymous visitors
- Model turns are rendered with `innerHTML` through DOMPurify, using the same tag/attribute allowlist as `ui.js`'s chat window — GuiPT's replies carry HTML (links, line breaks) that needs to render, not display as raw markup
- **Read-only by design** — no delete button. A chat is deleted from the Firebase Console instead, which the ↗ next to its Firestore ID opens straight to the document (`~2F<collection>~2F<id>`)
- Each row's header has labeled copy buttons, with the IDs only as hover tooltips: `Firestore ID` (the document ID), `Sonic ID` (Sonic only, `sonicSessionId`; its ↗ opens Ellmo Inspector at `?requestId=<id>`) and `Transcript` — the turns in order plus `micUsed`, as JSON, for pasting elsewhere
- Filters are the collection, a date range with 7d/30d/90d presets, and an expand/collapse-all toggle over the result list. There's no Load button: every filter queries on its own (date edits debounced, since typing fires `change` per segment), and only the newest query renders

### Service Health Dashboard

`modules/admin-status.js` polls each service's health endpoint on page load and on the header's `Refresh` button — never on an interval — and paints a status pill (dot + label) plus a detail line per card. When a service is up, that line shows the commit hash as a click-to-copy code badge. GuiDo and claudeCodeGateway are live checks; details on those endpoints live in their own repos, not here. A static `Servers` card (code-server and runtime-server) sits above the On Air sign card, with an icon in its header linking to the PM2 bucket both services run in. The cards sit in two `.card-column`s so each column's cards split that column's height independently.

The On Air sign card reads the Pico's heartbeat from the public Adafruit IO feed `pico` (keyless, CORS `*`), which the Pico writes every minute: `{state, uptime_s, mem_used, mem_free}`. Up if the heartbeat is under 150s old (2.5 heartbeats); the stats stay filled when down, as the Pico's last report. Its stats sit two pairs per row to keep the card about as short as its column neighbors. Its OFF/YELLOW/RED buttons `POST` `{state, minutes?}` to Guiddleware's `/onairsign` with the Firebase ID token; yellow/red hold for 60 minutes (`SIGN_HOLD_MINUTES`) instead of the Pico's 5-minute default. The state shows optimistically (the heartbeat lags up to 60s) and reverts with an error line if the call fails. Guiddleware's CORS allows `guiruggiero.com` and the ngrok testing domain, so the buttons also work through ngrok. The firmware side is in `on-air-sign/mac/pico/CLAUDE.md` — keep the two in sync if the heartbeat changes.

### Firebase Sign-In

`modules/admin-auth.js` uses a separate, more privileged Firebase Web API key than `modules/firebase.js`'s (Identity Toolkit access, not just Firestore) — restricted the same way, by API + HTTP referrer, in Google Cloud Console. Google sign-in itself is backed by its own OAuth 2.0 Client ID, also restricted there.

### Chat Log Schema

```
{v1|dev}/{chatID}
  origin: string
  start: Timestamp
  turnCount: number
  duration: number    // Minutes, and only written from turn 2 onward — single-turn chats have no duration
  turns: {"1": {user, model}, "2": {user, model}, ...}   // Keys are stringified numbers, so they need a numeric sort
```

Sonic voice chats go to `voice` (`voice-dev` on ngrok) with the same shape, plus a few fields:

```
{voice|voice-dev}/{chatID}
  ...same as above
  sonicSessionId: string   // Nova Sonic's session ID, for cross-referencing Sentry and AgentCore logs
  ttfa: number             // Seconds from starting the conversation to the first audio byte
  micUsed: boolean         // Whether the mic was ever on during the session
  turns: {"1": {user, model, input}, ...}   // input is "spoken" (user text is Nova's ASR transcript) or "typed"
```

The opening greeting isn't logged (it answers a synthetic "Hello", not the visitor), and `model` only holds what actually played, so a barge-in truncates it. The admin viewer shows `input` next to the turn number and `ttfa` beside the turn count and duration, and copies `sonicSessionId` from the row header's `Sonic ID` button.

### Firestore Rules

**The Firebase Console is the source of truth for the rules** — edited and deployed there directly, relying on the Console's own revision history instead of git. `firestore.rules` exists locally only as a gitignored scratch copy for review; it's never committed, never deployed via the CLI, and `firebase.json` has no `firestore` config pointing at it. This repo is public on GitHub, and the rules aren't something to publish.

`create` and `update` are open to anonymous visitors on the `v1`/`dev` collections, but only if the document shape passes `reviewFieldsAreValidTypes()` (field types, string/map size caps) and only touches the expected keys — real validation, not just a collection-name check. Updates check `diff()`'s `addedKeys()`/`changedKeys()`/`removedKeys()` separately rather than one `affectedKeys()` allowlist: nothing can be removed, `duration` may be added (it first appears at turn 2), and on `voice`/`voice-dev` `sonicSessionId` and `ttfa` are write-once — addable if they arrived after the create, never changeable — while `micUsed` can still flip mid-session. `list`/`get` are restricted to the owner's UID, and `delete` is denied outright for everyone, always — deletion only ever happens from the Firebase Console, which bypasses rules entirely, so there's no delete path to secure on the client side at all.

## Deployment Pipeline

Pushing to the `prod` branch triggers the minification workflow:

1. `npm ci` installs the minifier CLI tools (`html-minifier-next`, `lightningcss-cli`, `terser`) as pinned root `devDependencies` — not `npm install -g ...@latest` — so version bumps go through Dependabot/`npm update` like any other dependency, reviewable before they ever touch a live deploy; `node_modules/.bin` is added to `$GITHUB_PATH` so the rest of the steps can call them by bare name
2. HTML → html-minifier-next
3. CSS → lightningcss-cli
4. JS → terser (with source maps)
5. Source maps uploaded to Sentry (before the delete step, since sourcemaps need the plain `.js` files and their content to still be present)
6. Delete files not needed at runtime: `.github/`, `apps/`, `guipt/`, `sonic/agentcore/`, `sonic/scripts/`, `node_modules/` (created by step 1 — must be removed here since `.gitignore` itself is also deleted, so it's no longer around to keep it out of the commit), the plain (non-`.min.js`) `modules/*.js` sources, and dev-only root files (`CLAUDE.md`, `package.json`, etc.). **Any new backend-only or dev-only directory must be added to this list** so its source doesn't leak into the public `prod-min` branch
7. Minified output force-pushed to `prod-min` branch
8. GitHub Pages serves from `prod-min`; Cloudflare cache is then purged

The `main` branch is for development; `prod` is the pre-minification source; `prod-min` is what's actually served at guiruggiero.com. To tell whether a fix is live in production, don't use commit dates on `main` — check `git merge-base --is-ancestor <sha> origin/prod` (or `origin/prod-min`) and the `createdAt` of the latest `gh run list --branch prod` minification run, which is when browser caches really start counting.

### Syncing `main` into `prod`

`main` and `prod` have diverged commit histories (past syncs went through squash-merged PRs), so `git push origin main:prod` is rejected as non-fast-forward even when the two branches' file contents already match. Don't force-push to reconcile them. Instead, open a PR with base `prod` and head `main`, then merge it with a regular merge commit (`gh pr merge <number> --merge`) — not squash or rebase, to preserve history. Before merging, `git diff --stat origin/prod origin/main` is worth a look to confirm nothing surprising is riding along.

Name the sync PR for its actual content, not the mechanical action — e.g. `Weekly update`, `Bump dependencies`, or (for a large mixed batch) `Too many changes/updates accumulated to list`, not a generic title like "Sync main into live".

The SonarCloud check on these PRs can fail on pre-existing findings unrelated to the sync itself (e.g. Dockerfile or Python findings in `sonic/agentcore/`) — it isn't a required check, so a failure there doesn't block merging; confirm via `~/.claude/sonarqube.sh` that the findings predate the sync before merging anyway.

`guipt/` is deployed independently and separately from this pipeline (`npm run deploy` from within `guipt/`, using whatever is on local disk — not tied to git state). Never let `guipt/index.js` reference files that aren't committed to git (e.g. an in-progress `tools/`/`utils/` addition) — it'll deploy fine from local disk, but leaves `main` broken for a fresh clone and creates drift between what's committed and what's actually running in production. Currently untracked in git: `guipt/index.wip.js` (the committed `index.js` plus a tool-calling loop) and the files only it uses — `guipt/tools/` (`bookMeeting.js`, `getAvailableSlots.js`, `getCurrentDateTime.js`, `sendEmail.js`), `guipt/utils/calCom.js` and `guipt/scripts/testCalCom.js`. This is unfinished work, not in the committed `index.js`; commit it or discard it so it isn't lost with the working tree (and delete this note).
